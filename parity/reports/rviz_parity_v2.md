## How this was measured

- REAL: `parity/fixtures/rviz/` (read `STATUS_AND_LISTS.md` first). Paths in the table are relative to `parity/`.
- SITE: `http://localhost:8080/rviz.html?robot=tb3_burger` and `?robot=ur5e` in headless Chromium (Playwright), driven like a student:
  `colcon build`, `source install/setup.bash`, `rviz2` in the terminal (fresh window), `ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py`,
  `ros2 launch ur_simulation_gz ur_sim_moveit.launch.py ur_type:=ur5e`. The same `.rviz` files the real rviz2 loaded
  (`property_trees/input_all_default_displays.rviz`, `status_tb3/input_status_map.rviz`, `tools_tb3/input_tools_odom.rviz`) were loaded with the
  viewer's `loadConfig` (what File > Open Config does). State read from `window.__rvizViewers[0]` (`state()`, `configText()`) and the DOM; tool clicks are real mouse drags on the canvas.
- Scripts and raw output: `parity/browser_out/rviz_v2/` (`tb3_audit.mjs`, `tb3_audit2.mjs`, `moveit_audit.mjs`, `extras.mjs`, `compare_props.py`, `*.json`, `site_*.png`).
- Chromium had to render WebGL on the machine GPU (`--use-angle=gl`, `rviz_v2/lib.mjs`): with SwiftShader (tests/real-lib.mjs `webgl:true`) the page runs at < 1 frame/s once the
  Gazebo window is open, and screenshots / pointer input time out (`rviz_v2/probe3.mjs`). This is a test-harness note, not a site verdict.
- The real-machine plugin set is larger than a stock ros-jazzy-desktop (moveit, nav2, rtabmap, rviz_2d_overlay); environment-dependent entries are UNVERIFIED (L12).

  `frame-manager.js` `getGlobalStatus()` reports from the registry; S2/S4/S5 – `rviz.js` uses the text `Fixed Frame [..] does not exist` for Grid/TF/Axes/RobotModel when the fixed frame is missing.
