RViz in your browser

RViz2 started the way it is on Ubuntu: a robot description package is built with colcon, and a launch file (Python or XML) starts robot_state_publisher, joint_state_publisher_gui and rviz2 with a saved .rviz config. Move a slider and the robot moves: /joint_states → robot_state_publisher → /tf → RViz.

Robots with sensors also have sim.launch.py: Gazebo Harmonic runs the robot's lidar, camera, depth camera and IMU (declared in <gazebo> tags of the URDF), ros_gz_bridge brings their topics to ROS 2, and RViz shows the scan, point cloud, images and IMU. Drive the mobile robots with ros2 run teleop_twist_keyboard teleop_twist_keyboard in a new terminal.

Every arm also has a MoveIt 2 package (<robot>_moveit_config, laid out like the MoveIt Setup Assistant makes it): drag the orange interactive marker at the tool, choose the OMPL, Pilz, CHOMP or STOMP planning pipeline, and Plan & Execute around the table, box and post of the work cell, with mock hardware or in Gazebo. Download this workspace gives the same packages as a ROS 2 Jazzy workspace for Ubuntu 24.04; their real.launch.py and README connect the real robot through its maker's driver (USB, Ethernet, CAN or Wi-Fi).

  1. xacromy_robot.urdf.xacro → URDF text

  3. joint_state_publisher_guisliders → publishes /joint_states

How it works, and its limits
    
The terminal is ROS2Lab's practice terminal: a pretend Ubuntu 24.04 with ROS 2 Jazzy. colcon build installs the package's launch, urdf, meshes and rviz folders only if CMakeLists.txt has the install(DIRECTORY ...) rule; ros2 launch reads your Python or XML launch file, runs xacro, and starts the nodes. Try ros2 node list, ros2 topic list, ros2 topic echo /joint_states, ros2 run tf2_ros tf2_echo base_link <link> or ros2 launch <package> display.launch.py gui:=false in a new terminal tab.

    
The RViz window is ROS2Lab's practice RViz2, built with three.js. It copies RViz2's displays, properties, tools and messages, so the same steps work with the real rviz2 on Ubuntu. It is not the real rviz2 program. MoveIt here is ROS2Lab's practice move_group: it reads the package's SRDF, kinematics, joint limits and pipeline files, covers each link with collision spheres fitted to its meshes, and plans with OMPL-style sampling planners, Pilz PTP/LIN/CIRC, CHOMP and STOMP; the same package runs with the real MoveIt 2 (tested with ros-jazzy-moveit). RViz, ROS and ROS 2 are projects of Open Robotics; MoveIt is a project of PickNik Robotics and the MoveIt community; ROS2Lab is an independent course and is not affiliated with or endorsed by Open Robotics.

    
Gazebo here is a small stand-in for Gazebo Harmonic: it reads the world SDF and the robot's <gazebo> sensor tags, renders cameras, casts lidar rays and drives DiffDrive robots, but it has no physics (robots do not fall or collide). The rules are the real ones: sensors publish only if the world loads gz-sim-sensors-system (and gz-sim-imu-system for IMUs), ROS 2 sees them only through ros_gz_bridge, the header frame is <gz_frame_id>, and Gazebo Classic plugins (libgazebo_ros_*.so) do nothing in Harmonic. The robot models come from their makers' public ROS repositories (licences are in each package); meshes were simplified to load faster.

    
When connected through rosbridge, it subscribes to /robot_description, /tf, /tf_static and to the topic of every display you add (LaserScan, PointCloud2, Image, Camera, Imu, Odometry, Path, Map, Marker...), and the RViz tools publish /goal_pose, /initialpose and /clicked_point. Browsers only allow a secure page to talk to rosbridge on the same computer (localhost); Chrome may ask you to allow access to apps on this device. For a robot on the network, run this page on the robot's computer or forward the port with ssh -L 9090:localhost:9090 user@robot.
